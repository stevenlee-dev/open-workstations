# Open Workstations

[English](README_EN.md)

一个可自行部署的工位申请系统。它把空间布局、工位类型和使用期限放在配置文件里，适合实验室、创客空间或共享工作室按自己的规则改造。

项目由 [@sandylee6725-crypto](https://github.com/sandylee6725-crypto) 发起和维护。这个仓库是独立的开源实现，只包含示例房间与演示配置，不包含任何实际实验室的布局、账号或申请记录。

## 能做什么

- 按配置展示多个空间及其工位；每个工位可单独指定流动、轮流或固定类型。
- 申请人注册、登录、填写使用计划和预期成果，可附最多 3 个文件。
- 同一工位可以同时收到多份待审核申请。管理员批准时，服务端会在事务中检查日期冲突。
- 申请人查看、撤回自己的待审核申请；管理员查看申请、下载材料、通过或驳回并留下意见。
- 到期后工位自动退出使用状态；继续使用要重新申请。

这是一个可以运行和继续开发的基础版本，不是某个单位现行制度的复制品。首次公开版采用本地账号；短信验证、校内统一身份认证、邮件提醒和在线编辑布局尚未接入。用于真实申请前，请先完成本单位的身份认证和数据保护方案。详见 [部署说明](docs/deployment.md)。

## 快速运行

需要 Node.js 24.15 或更新的 24.x 版本。

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

访问 `http://localhost:4312`。示例配置默认开放自助注册，申请人可以试用流程。管理员需要先通过 `ADMIN_PASSWORD` 环境变量设置初始密码，然后执行：

```bash
npm run admin:create -- reviewer "示例管理员"
```

创建完成后清除该环境变量；不要把密码写在命令参数、配置文件或提交记录中。开发前端时，在另一个终端运行 `npm run dev`，前端访问 `http://localhost:5173`，API 会代理到本地 4312 端口。

## 把示例改成自己的空间

复制 `config/site.example.json`，再在 `.env` 中把 `CONFIG_FILE` 指向新文件。这个文件控制站点名称、时区、注册与申请开关、学期日期、空间和工位。每个工位有独立 ID、类别及 `x/y/width/height` 坐标，页面按空间的 `width/height` 缩放展示。

| 类型            | 默认期限算法                 | 可修改项                         |
| --------------- | ---------------------------- | -------------------------------- |
| 流动 `flexible` | 从选定日期起，最多 7 天      | `maxDays`、文案、各工位归类      |
| 轮流 `rotating` | 不晚于开始日期所在月份的月底 | 文案、各工位归类                 |
| 固定 `fixed`    | 选定学期的末日               | `terms` 中的学期起止、各工位归类 |

例如，增加一个工位只需在房间的 `seats` 数组里加入对象：

```json
{ "id": "LAB-07", "label": "07", "type": "rotating", "x": 120, "y": 90, "width": 90, "height": 70 }
```

服务启动时会校验配置，工位 ID 必须全局唯一。运行中的工位 ID 不要随意修改：历史申请使用该 ID 关联。更完整的字段说明见 [布局与规则配置](docs/configuration.md)。

## 项目结构

```text
config/       示例布局与规则
server/       Express API、SQLite 存储、权限和日期策略
src/          Vue 界面
scripts/      初始化管理员等命令
tests/        日期策略和申请冲突测试
docs/         配置、部署、接口和架构说明
```

前端和后端由一个 Node 服务提供；开发时 Vite 只负责前端热更新。数据库与附件保存在 `DATA_DIR` 下的 SQLite 文件中，默认 `.data/`，已被 Git 忽略。常用命令：`npm test`、`npm run build`、`npm run check`。
