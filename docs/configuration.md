# 布局与规则配置

从 `config/site.example.json` 复制一份站点配置，不要直接用示例房间承载真实数据。修改后重启服务；启动时会检查字段类型、日期格式和 ID 唯一性，配置错误会阻止启动。

`siteName` 与 `organization` 只用于页面标题；`timeZone` 是计算“今天”和到期时间的 IANA 时区名。`registrationOpen` 控制自助注册；`applicationOpen` 控制新申请提交。关闭申请窗口不会撤销已有申请。

`rooms` 可以包含多个空间。每个空间的 `width`、`height` 构成画布大小，工位的 `x`、`y`、`width`、`height` 是画布内的矩形坐标。画布会随页面宽度等比缩放。工位 `id` 是数据库关联键，需在所有空间中唯一且保持稳定；`label` 是地图上给用户看的短名称。`type` 只能是 `flexible`、`rotating` 或 `fixed`。改变工位类型只影响新申请，旧申请保留提交时的类别和日期。

`seatTypes.flexible.maxDays` 计算包含首尾两日。例如 10 月 1 日至 10 月 7 日为 7 天。`rotating` 的结束日期不得晚于开始日期所在月份的最后一天。`fixed` 需要选一个 `terms` 条目：开始日不能早于该学期起点，结束日必须等于学期末。学期并非自动按年份生成，因此每学年需提前补入下一组日期。若一个学期没有开放，删除或不添加该条目即可；注册和申请是否开放由管理方开关控制。

示例中的空间、工位和学期都不是任何单位的正式规则。上线前请先确定工位编号、开放时间、审核责任、使用期限和材料要求，再修改配置。应用不会迁移或删除因配置改动而不再显示的历史工位数据，调整已投入使用的 ID 前请备份数据库。
